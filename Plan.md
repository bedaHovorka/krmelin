# Plan.md — Krmelin

> Implementation plan for Claude Code. Version 1.3 (incorporates OSTRAJava issue #14 exception design, corrected Flakanci scope, ASCII-only keyword rule, `chuj` as canonical null).

## Mission Statement

**Krmelin** is a satirical programming language: *Kotlin, but through a Moravian/Ostrava lens.* Source-language keywords are replaced with authentic Ostrava-dialect ("ostravština" / "po našymu") vocabulary — the short-voweled, penultimate-stress, German/Polish-influenced miners' slang of the Moravian-Silesian region — while a genuine, well-engineered transpiler sits underneath. The joke lives in the surface syntax and the standard-library names; the compiler is real: a lexer, recursive-descent + Pratt parser, typed AST, resolver, minimal type checker, and a source-to-source code generator emitting runnable Kotlin. Krmelin is a spiritual successor to Tomáš Kohout's OSTRAJava, but it is a **clean-room reimplementation targeting Kotlin**, not a fork.

## 2. Chosen Technology Stack

| Concern | Choice | Justification |
|---|---|---|
| Implementation language | **Kotlin (JVM, Kotlin 2.x)** | The parody *is* Kotlin; dogfooding. Data classes + sealed classes make AST modeling and visitors concise. |
| Parser technology | **Hand-written recursive-descent + Pratt expression parser**, hand-rolled lexer | Maximum control over error messages (parody-voice diagnostics are a core requirement), no generator build step, trivial source-position tracking, easy incremental development. |
| Backend target | **Transpile to Kotlin source**, compile/run via kotlinc | Fastest path to end-to-end: Krmelin semantics map ~1:1 onto Kotlin, so lowering stays thin. Golden-file testing of generated `.kt` is straightforward. |
| Build system | **Gradle (Kotlin DSL)** | Standard for Kotlin; application + shadow-jar plugins. |
| CLI library | **Clikt** | Idiomatic Kotlin, composable subcommands, clean option DSL. |
| Test framework | **JUnit 5** for the compiler; **PorubaUnit** for Krmelin programs | JUnit 5 is the JVM standard; PorubaUnit is a required deliverable, self-contained so output format is fully controlled. |

**Backend alternatives considered:** Java source (more verbose codegen; no native null-safety or data classes → more lowering); JVM bytecode via ASM (no external toolchain but far more effort); JavaScript/TypeScript (fast startup, easy distribution, but loses Kotlin symmetry). Kotlin wins on time-to-first-demo, the dominant constraint.

**Parser alternatives considered:** ANTLR4 (powerful, but adds a build step and fights custom error recovery); parser-combinator libraries (less transparent for diagnostics).

**Fallback stack:** TypeScript/Node, hand-written lexer + recursive-descent/Pratt, transpiling to JavaScript, CLI via commander, tests via Vitest.

## 4. Language Design

### 4.1 Dialect grounding and orthographic rules

Keywords are grounded in documented ostravština / lašské nářečí (Lach dialect) sources. Characteristic markers that make the design feel authentic:

- **No long vowels; everything clipped** — as community primers put it, "ostravština nema dluhe samohlasky … na vic neni čas."
- **Stress on the penultimate syllable** — a documented Lach feature: "přízvuk leží vždy na předposlední slabice slova nebo slovního celku."
- **`v` → `f`** (sfeter, fčela), **`y` after `ř`** (křyvy, břydky), **soft `tě` → `če`** (ešče, klešče).
- **German and Polish mining borrowings**: fajront (end of shift), šichta (shift), cymerhajer, dratban.
- Locals call it "po našymu"; it belongs to the **Lach dialect group**, historically shaped by Czech, Polish, German, and Silesian.

Vocabulary drawn on below: **kaj** (where/which), **bo** (because), **toz/tož** (well then), **fajny** (fine, good), **nyt** (no), **cyp** (fool; general intensifier), **robic** (to work), **rubat** (to hew/mine), **fajront** (end of shift), **banik/haviř** (miner), **šichta** (shift), **flákanec** (a whack/slap; also a slab), **pultík** (bar counter), **bitka** (a brawl), **chachar** (rascal), **dryst** (drivel), **jedynak** (only child), **ci** (or), **aj** (and/also), **zdybat** (to catch), **dupej/migej** (get moving).

#### Hard rule: keywords are ASCII-only

**Every Krmelin reserved word must match `^[@A-Za-z_][A-Za-z0-9_]*$` — no diacritics.** OSTRAJava follows this convention throughout (`tryda`, `kaj`, `davaj`, `boinak`, `aj`, `pyco`, `pultik`, `bitka`, `dostanes`, `rozdava` — not one diacritic among them), and it matters practically: a keyword you cannot type on a US keyboard is an ergonomics tax on a language meant to be fun. Dialect spelling is preserved phonetically instead (`sachta`, `mozej`, `jedynak`, `@Sichta`).

The rule constrains **reserved words only**. Identifiers, string literals, comments, and diagnostic message text remain full Unicode — user code may freely name things `příkopa` or print `"fajront, chlapi"`.

Enforce this with a lexer test asserting that every entry in `Keywords.kt` matches the pattern, so the convention cannot drift as contributors add keywords. Document it as §1 of `docs/language-spec.md`.

The exception vocabulary (`pultik` / `bitka` / `fajront` / `dostanes` / `rozdava` / `Flakanec`) follows the pub-brawl metaphor proposed in OSTRAJava issue #14: you stand at the bar counter, someone dishes out a whack, you get one, a brawl breaks out. Krmelin adds `fajront` for `finally`, which issue #14 did not cover, and drops OSTRAJava's `pyco` statement terminator.

Constructs kept with Kotlin names to limit scope: generics `<>`, lambdas `{ }`, import aliasing.

### 4.3 EBNF grammar (MVP subset)

```ebnf
program        = { topLevelDecl } ;
topLevelDecl   = packageDecl | importDecl | classDecl | funDecl | propertyDecl ;
packageDecl    = "sachta" qualifiedName NL ;
importDecl     = "privezt" qualifiedName [ "." "*" ] NL ;

classDecl      = { annotation } ( [ "zapisnik" ] "tryda" IDENT [ paramList ] [ classBody ]
               | "jedynak" IDENT [ classBody ]
               | "predpis" IDENT [ classBody ] ) ;
classBody      = "{" { member } "}" ;
member         = funDecl | propertyDecl ;

funDecl        = { annotation } "robota" IDENT paramList
                 [ ":" type ] [ "rozdava" type { "," type } ] funBody ;
annotation     = "@Sichta" | "@Parta" ;
funBody        = block | "=" expr NL | NL ;   (* the bare-NL form declares an abstract
                                                 function and is legal only inside predpis *)
paramList      = "(" [ param { "," param } ] ")" ;
param          = [ "toz" | "mozej" ] IDENT ":" type [ "=" expr ] ;

propertyDecl   = ( "toz" | "mozej" ) IDENT [ ":" type ] [ "=" expr ] NL ;

block          = "{" { statement } "}" ;
statement      = propertyDecl
               | ifStmt | whenStmt | forStmt | whileStmt
               | returnStmt | breakStmt | continueStmt
               | tryStmt | throwStmt
               | exprStmt ;

ifStmt         = "kaj" "(" expr ")" block
                 { "kajtez" "(" expr ")" block }
                 [ "boinak" block ] ;
whenStmt       = "podle_teho" [ "(" [ expr ] ")" ] "{" { whenBranch } "}" ;
whenBranch     = ( exprList | "boinak" ) "->" ( expr | block ) ;
forStmt        = "prokazdy" "(" IDENT "v" expr ")" block ;
whileStmt      = "rubaj" "(" expr ")" block ;
returnStmt     = "davaj" [ expr ] NL ;
breakStmt      = "zdybat" NL ;
continueStmt   = "dalej" NL ;
tryStmt        = "pultik" block { "bitka" "(" param ")" block } [ "fajront" block ] ;
throwStmt      = "dostanes" expr NL ;
exprStmt       = expr NL ;

type           = IDENT [ "<" type { "," type } ">" ] [ "?" ] ;

expr           = assignment ;
assignment     = logicalOr [ "=" assignment ] ;
logicalOr      = logicalAnd { "ci" logicalAnd } ;
logicalAnd     = equality { "aj" equality } ;
equality       = comparison { ("==" | "!=") comparison } ;
comparison     = elvis { ("<" | ">" | "<=" | ">=") elvis } ;
elvis          = additive [ "?:" elvis ] ;
additive       = multiplicative { ("+" | "-") multiplicative } ;
multiplicative = unary { ("*" | "/" | "%") unary } ;
unary          = ("!" | "-") unary | postfix ;
postfix        = primary { callSuffix | "." IDENT | "?." IDENT } ;
callSuffix     = "(" [ argList ] ")" ;
primary        = literal | IDENT | "(" expr ")" | stringTemplate | lambda ;
literal        = INT | FLOAT | STRING | "fajne" | "nyt" | "chuj" ;
NL             = ? newline or ';' ? ;
```

Statement termination is **newline-significant** (like Kotlin), not OSTRAJava's `pyco` terminator. The parody lives in keywords, not punctuation noise.

**Exceptions — the pub brawl:**

```
robota drystaniPredMikrofonem() : Dryst rozdava Flakanec {
    kaj (mikrofon != chuj aj mikrofon.zapnuty) {
        davaj "Hanzel desitka"
    } boinak {
        dostanes Flakanec("mikrofon je vypnuty")
    }

robota rynek() {
    pultik {
        zarvat(drystaniPredMikrofonem())
```

```kotlin
@Throws(Flakanec::class)
fun drystaniPredMikrofonem(): String {
    if (mikrofon != null && mikrofon.zapnuty) {
        return "Hanzel desitka"
    } else {
        throw Flakanec("mikrofon je vypnuty")
    }
}

fun main() {
    try {
        println(drystaniPredMikrofonem())
    } catch (f: Flakanec) {
        println("dostal sem: ${f.zprava}")
    } finally {
        println("fajront, chlapi")
    }
}
```

### 4.5 `rozdava` semantics

`rozdava` is parsed, stored on the `FunDecl` AST node, surfaced in generated documentation, and emitted as a Kotlin `@Throws` annotation. It is **never type-checked** — Kotlin has no checked exceptions, and enforcing them would mean building a whole effect system for a joke language. Calling a `rozdava` function without a `pultik` is legal. Document this explicitly in the spec so the behavior is not mistaken for a bug.

### 4.6 Prelude / standard library

A generated Kotlin prelude maps Krmelin names to Kotlin:

| Krmelin | Kotlin |
|---|---|
| `Dryst` | `String` |
| `Cyslo` | `Int` |
| `CysloDesetinne` | `Double` |
| `Bul` | `Boolean` |
| `Chachar` | `Char` |
| `Halda<T>` | `List<T>` |
| `Kupa<K,V>` | `Map<K,V>` |
| `.naDryst()` | `.toString()` |
| `.dylka` | `.length` / `.size` (extension) |
| `pravit(x)` | `print(x)` |
| `zarvat(x)` | `println(x)` |

**On `chuj`:** `chuj` is the **canonical** null literal — it is what the spec, examples, error messages, and generated code all use, and the `Chujovy` root carries through to the exception hierarchy (§7) and the assertion API (§6). `nic` is accepted as a milder synonym; the lexer maps both spellings to `TokenType.NULL` and emits Kotlin `null` either way, so both compile identically and neither is second-class.

Be aware of what this chooses. `chuj` is a Polish borrowing whose register is harsher than its Czech equivalents — nearer the strongest English four-letter word than to "crap" — and null is structural rather than decorative: it appears in every null check, every safe-call example, every nullability diagnostic, and the README's first code block. Making it canonical sets the register of the project's public face. That is a legitimate choice for a language in this tradition (OSTRAJava made it and found its audience), but it should be made deliberately, not drifted into. State it once in `docs/keywords.md` — Krmelin's vocabulary includes strong regional slang — plainly and without apology, and do not belabour it elsewhere.

## 5. Compiler Pipeline Architecture

```
.krm source
  → Lexer        → List<Token>
  → Parser       → AST (CompilationUnit)
  → Resolver     → AST + SymbolTable (bindings resolved, scopes)
  → TypeChecker  → AST + checked types (minimal)
  → Lowering     → desugared AST
  → KotlinEmitter→ .kt source
  → kotlinc      → run or jar
```

**1. Lexer (`lexer/`)** — char reader → tokens. Every `Token` carries `SourceSpan(file, startLine, startCol, endLine, endCol)`. `Keywords.kt` is the single source of truth mapping keyword strings → `TokenType`, and is subject to the ASCII rule test (§4.1). Matching is **case-sensitive** (a deliberate divergence from OSTRAJava, which was case-insensitive) for cleaner "did you mean" diagnostics. Handles comments (`//`, `/* */`), string templates, numeric literals.

**2. Parser (`parser/`)** — recursive descent for declarations and statements, one method per nonterminal; Pratt parser for expressions with the §4.3 precedence table. **Error recovery is panic-mode**: record a `Diagnostic`, then skip tokens until a newline or a sync keyword (`robota`, `tryda`, `kaj`, `rubaj`, `pultik`, `}`), so multiple errors surface per run.

**3. AST (`ast/`)** — sealed hierarchies for exhaustive `when`. Every node carries a `span`.

**4. Resolver (`resolve/`)** — `Scope` (lexical chain: block → function → class → file → prelude), `SymbolTable` (names → declarations), `Resolver` (walks AST, attaches bindings to `NameExpr`, reports undeclared/duplicate/shadowing).

**5. TypeChecker (`types/`)** — **intentionally minimal**: primitives, declared types, nullability flag. Checks assignment compatibility, `davaj` against the declared return type, conditions are `Bul`, call arity. Inference only for `toz`/`mozej` with an initializer. No generic inference beyond pass-through, no overload resolution beyond name+arity. Anything harder is emitted and left to kotlinc.

**6. Lowering (`lower/`)** — desugars so codegen stays dumb: subject-less `podle_teho` → `when {}`; `prokazdy (x v xs)` → `for (x in xs)`; string templates normalized; `rozdava` → `@Throws`. Safe-call and elvis pass through (Kotlin has them natively).

**7. KotlinEmitter (`codegen/`)** — visitor over the lowered AST producing formatted Kotlin. Emits the prelude import, maps keyword nodes, preserves user identifiers. **Deterministic formatting** (fixed indentation, no timestamps) so golden tests are stable.

### AST node inventory

- **Decl:** `CompilationUnit`, `PackageDecl`, `ImportDecl`, `ClassDecl` (`isData`, `isObject`, `isInterface`, `params`, `members`), `FunDecl` (`isTest`, `throwsTypes`), `PropertyDecl` (`isMutable`), `Param`
- **Stmt:** `Block`, `PropertyStmt`, `IfStmt`, `WhenStmt`, `ForStmt`, `WhileStmt`, `ReturnStmt`, `BreakStmt`, `ContinueStmt`, `TryStmt` (`catches`, `finallyBlock`), `ThrowStmt`, `ExprStmt`
- **Expr:** `IntLit`, `FloatLit`, `StringLit`, `BoolLit`, `NullLit`, `StringTemplate`, `NameExpr`, `BinaryExpr`, `UnaryExpr`, `CallExpr`, `MemberExpr`, `SafeMemberExpr`, `ElvisExpr`, `AssignExpr`, `LambdaExpr`, `ParenExpr`
- **Type:** `NamedType` (`name`, `nullable`, `typeArgs`)

## 6. PorubaUnit Specification

Named after **Poruba**, a large district of Ostrava (~62,000 residents). PorubaUnit is Krmelin's xUnit-style framework, inspired by the community proposal in OSTRAJava issue #15 but reimplemented clean-room with a cleaner API.

### Marking and discovery

A test is any `robota` annotated **`@Sichta`** ("a shift"). Tests may be grouped in a `tryda` annotated `@Parta` ("a crew"). Discovery: `krmelin test` scans `tests/**/*.krm`, transpiles them, and the emitter records every `@Sichta` function into a generated `KrmelinTestMain.kt` registry. Discovery is resolved at code-gen time — no runtime reflection.

### Assertion API

Implemented in `runtime/PorubaUnit.kt`:

| PorubaUnit | Meaning | Kotlin equivalent |
|---|---|---|
| `musi_byt(actual, expected)` | "must be" | `assertEquals` |
| `nesmi_byt(actual, expected)` | "must not be" | `assertNotEquals` |
| `je_fajne(cond)` | "is fine" | `assertTrue` |
| `je_nyt(cond)` | "is nope" | `assertFalse` |
| `je_chuj(x)` | assert null | `assertNull` |
| `neni_chuj(x)` | assert not null | `assertNotNull` |
| `ma_dostat { ... }` | "should get one" — asserts the block throws | `assertThrows` |
| `blizko(a, b, tolerance)` | float approximate equality | `assertEquals(a,b,δ)` |

Each takes an optional trailing message and reports the source span of the failing call.

### Runner behavior

Runs every discovered `@Sichta`. Failures are isolated — one failed assertion fails only its test. Uncaught `Flakanec` (or any JVM throwable) is reported as an **error**, distinct from an assertion **failure**. Order is deterministic: by file, then declaration order.

### Console output

Passing:

```
PorubaUnit — šichta začíná
  ✓ delka_chuj_vraci_nulu          (0 ms)
  ✓ pozdrav_zdravi_spravne         (1 ms)
  ✓ mikrofon_vypnuty_rozdava       (2 ms)

Fajront: 3 prošly, 0 spadlo, 0 chyb — za 41 ms
```

Failing:

```
PorubaUnit — šichta začíná
  ✓ pozdrav_zdravi_spravne         (1 ms)
  ✗ delka_chuj_vraci_nulu          (1 ms)
      musi_byt spadlo v tests/e2e/delka_test.krm:7:9
      čekal sem:  0
      dostal sem: 3
  ! mikrofon_vypnuty_rozdava       (0 ms)
      dostal ju: ChujovyFlakanec v Mikrofon.krm:4

Fajront: 1 prošla, 1 spadla, 1 chyba — za 39 ms
```

Output prose may use diacritics; only keywords are ASCII-constrained (§4.1).

### Exit codes

- `0` — all tests passed
- `1` — at least one failure or errored test
- `2` — test sources failed to compile

### Backend mapping

The emitter generates `KrmelinTestMain.kt` with a `main()` that drives the PorubaUnit runtime over the registry. `krmelin test` compiles and runs it. **PorubaUnit does not depend on JUnit at runtime** — it is self-contained so output format and dialect voice are fully controlled.

## 7. Flakanci Specification

**`Flákanec` = a whack, a slap, a blow.** Per OSTRAJava issue #14, it is the dialect word for **Exception** — not "slacker." The metaphor is a pub brawl: you stand at the counter (`pultik`), someone dishes one out (`rozdava`), you get one (`dostanes`), a brawl breaks out (`bitka`), and eventually the shift ends regardless (`fajront`).

Flakanci is therefore **the exception hierarchy plus a deliberately chaotic demo**, and it is the required "chaotic module" from the project brief.

### `runtime/Flakanci.kt` — the hierarchy

| Krmelin type | Extends | Maps to |
|---|---|---|
| `Flakanec(zprava: Dryst)` | `RuntimeException` | base of the hierarchy |
| `ChujovyFlakanec` | `Flakanec` | `NullPointerException` — `chujovy` also carries "botched/worthless," so the name reads as both "the null whack" and "the whack you get when it's gone wrong" |
| `MimoBarak` | `Flakanec` | `IndexOutOfBoundsException` ("outside the building") |
| `DelenoNulou` | `Flakanec` | `ArithmeticException` |
| `ZlyDryst` | `Flakanec` | `NumberFormatException` / parse errors |

Every type exposes `.zprava` (message) and `.odkud` (the source span where it was thrown, when available).

### `examples/flakanci.krm` — the demo

A staged pub brawl: a loop that deliberately provokes each exception type in turn, catches them at varying nesting depths, rethrows one, and demonstrates that `fajront` runs on every path — normal exit, caught exception, and rethrow alike.

It exercises: nested `pultik`, multiple `bitka` clauses with subtype matching, rethrow, `fajront` ordering, `rozdava` on signatures, and interaction with nullable types. Output is **deterministic**, so the example doubles as an end-to-end golden test.

`examples/porubaunit_demo.krm` accompanies it with `@Sichta` tests over the Flakanci hierarchy — e.g. `deleni_nulou_rozdava_DelenoNulou`, `zly_dryst_ma_dostat` — demonstrating `ma_dostat` and PorubaUnit's error-vs-failure distinction end to end.

### Dependency note

Because Flakanci is the exception system rather than a standalone domain model, **Milestone 6 depends on Milestone 4 delivering exception codegen** (`pultik`/`bitka`/`fajront`/`dostanes` → `try`/`catch`/`finally`/`throw`). Sequence the milestones accordingly; this is not an independent example that can be built early.

## 9. Testing Strategy

| Layer | What to test | How |
|---|---|---|
| Keywords | every entry is ASCII-only (§4.1) | regex assertion over `Keywords.kt` |
| Lexer | token types, spans, string templates, comments, numerics | assert token lists |
| Parser | AST shape per construct; recovery yields multiple diagnostics | AST snapshot tests (serialize to text, diff) |
| Resolver/Types | undeclared, duplicate, arity, return-type, condition-type | table-driven: source → expected diagnostics |
| Codegen | generated Kotlin is correct and stable | **golden tests**: `foo.krm` + `foo.kt.expected` |
| End-to-end | compile + run, assert stdout and exit code | `e2e/` tests shelling out to the built jar |
| Exceptions | `fajront` runs on all paths; subtype matching; rethrow | e2e on `flakanci.krm` |
| Invalid syntax / types | errors surface correctly | `errors/` corpus with expected messages |
| PorubaUnit | pass/fail/error counting, exit codes, output format | run demo, capture stdout + exit code |

**Golden-file convention:** input and expectation side by side in `tests/golden/`; transpile, normalize, diff. A `-Dupdate.golden=true` flag regenerates expectations for intentional changes. Keep emitter formatting deterministic.

## 10. Error Message Design

**Helpful first, funny second.** Every diagnostic states (1) what is wrong, (2) exactly where, with a caret, and (3) how to fix it — then optionally one line of dialect flourish. The joke never replaces the information.

**Template:**

```
<severity>: <plain-language problem> [<code>]
  --> <file>:<line>:<col>
   |
 N |   <source line>
   |         ^^^^ <what specifically is wrong here>
   = pomoc: <concrete fix>
   = (optional one-line flourish)
```

`<severity>` is a dialect word: `hawaryja` (error), `pozur` (warning), `oznam` (info),
`dlubani` (debug), `sled` (trace). `<code>` carries the `HAV` prefix, short for
*hawaryja* — see the ranges in `docs/language-spec.md`.

**Examples:**

```
hawaryja: neznamy vyraz 'rubaš' [HAV110]
  --> examples/loop.krm:3:5
   |
 3 |     rubaš (i < 5) {
   |     ^^^^^ tohle neni klicove slovo
   = pomoc: myslel si 'rubaj'? klicove slova su bez diakritiky
```

```
hawaryja: robota 'delka' ma vracet Cyslo, ale 'davaj' nic nevraci [HAV342]
  --> src/util.krm:7:5
   |
 7 |     davaj
   |     ^^^^^ chybi hodnota za 'davaj'
   = pomoc: napis treba 'davaj 0', abo zrus navratovy typ
```

```
hawaryja: promenna 'hodinyspanku' neni deklarovana [HAV220]
  --> examples/haviri.krm:12:16
   |
12 |     davaj f.hodinyspanku > 8
   |            ^^^^^^^^^^^^ takova promenna tu neni
   = pomoc: nemyslel si 'hodinySpanku'? velka pismena hraju roli
```

```
hawaryja: podminka v 'kaj' musi byt Bul, ale je Cyslo [HAV331]
  --> src/main.krm:5:9
   |
 5 |     kaj (i + 1) {
   |         ^^^^^ tohle je Cyslo, ne fajne/nyt
   = pomoc: chtel si 'kaj (i + 1 > 0)'?
```

```
hawaryja: 'bitka' bez 'pultik' [HAV161]
  --> examples/flakanci.krm:9:1
   |
 9 | bitka (f: Flakanec) {
   | ^^^^^ bitka musi nasledovat po bloku 'pultik'
   = pomoc: obal riskantni kod do 'pultik { ... }' pred touhle bitkou
   = bez pultiku neni bitka
```

```
hawaryja: 'pozdrav' bere 1 argument, dal si 2 [HAV350]
  --> examples/demo.krm:9:5
   |
 9 |     pozdrav("cype", "banik")
   |     ^^^^^^^ o jeden navic
   = pomoc: 'pozdrav' ceka (mejno: Dryst)
```

Maintain an error-code index in `docs/language-spec.md`.

## 15. Risks and Non-Goals

**Do NOT build:**

- A custom bytecode VM or interpreter — transpile to Kotlin
- Full Kotlin coverage: no coroutines, no full generic inference, no operator overloading, no delegation, no reflection, no annotations beyond `@Sichta`/`@Parta`, no multiplatform
- Checked exceptions — `rozdava` is documentation only (§4.5)
- A sound or complete type system
- IDE tooling in v0.1 (LSP, debugger) — stretch only
- Backward compatibility with OSTRAJava syntax (`pyco`, `.tryda` files, case-insensitive keywords)

**Risks and mitigations:**

- *Jokes making code unreadable* → humor confined to keyword names and stdlib aliases; semantics stay 1:1 with Kotlin; diagnostics informative-first
- *Keyword ergonomics* → ASCII-only rule (§4.1), enforced by test so it cannot drift
- *Over-scoping the type system* → cap at the §5 minimal checker; defer everything else to kotlinc
- *Hardcoded jokes scattered through the compiler* → all dialect strings live in `Keywords.kt`, `Prelude.kt`, and `diag/`; no dialect literals inline in lexer, parser, or codegen logic
- *Crude vocabulary* (`chuj`, `cyp`) → deliberate and documented once in `docs/keywords.md` (§4.6); `nic` available as a milder synonym for anyone who wants it; README self-aware. Accept that this narrows where the language can be demoed
- *Toolchain coupling* (needs kotlinc on PATH) → detect and emit a clear diagnostic when missing; document prerequisites
- *Legal* → clean-room only; never copy OSTRAJava's parser, grammar, or stdlib; keep attribution courteous and non-endorsing
